功能

先报价，后花钱。

001 / 按能力调用，不按供应商

serp.google、x.search、keyword.volume、image.generate。每项能力对应多家供应商的路线，字段映射和批量合并都已处理好。

002 / 每条路线都有报价

价格来自本地缓存：供应商有实时价格接口就用实时价，没有就用公开价目表。你没有 Key 的路线也会报价，让你知道多一个 Key 能省多少。

003 / 花钱前重新报价

调用前一刻刷新价格。AnyAPI 会锁定最便宜的源，并关闭故障切换。

004 / 不越过的预算

每次运行先估价，超过 --max-usd 就拒绝。默认上限是 0.1 美元。

005 / 遇到 402 就停

遇到 402 返回退出码 2，第一次失败就停止。Agent 会把它理解为停下，而不是重试。

006 / 价格基线

最低价突然上涨时，运行会停下，等你确认接受新价格。

007 / 去重与批量

输入会先去重；供应商支持时，一组查询合并成一次批量调用。

008 / 每次调用都记账

响应会保存，费用记录在 ~/.getcheapapi。getcheapapi spend 按供应商和接口汇总。

009 / 媒体生成也一样

通过 Yir 生成图片、视频和语音，每个任务先报价，并在服务端设上限。

010 / 给 Agent 用的 Skill

把目录链接到 Claude Code、Codex 或其他 Agent。从克隆的仓库直接运行，不用安装包。

15 项能力，5 家供应商，一条命令。

所有路线都在一个目录文件里。价格和接口会变，新增或修正路线就提一个 Pull Request。

安装前

Q.001 / 免费吗？

免费。MIT 许可，不用注册，不收费。你用自己的 Key 直接向供应商付费。

Q.002 / 每家供应商都需要 Key 吗？

不需要，一个就够。没有 Key 的路线也会报价，你能看到多加一个 Key 能省多少。

Q.003 / 我的数据会经过你们的服务器吗？

不会。价格缓存、账本和保存的结果都在你本机的 ~/.getcheapapi 里。唯一的网络流量就是 API 调用本身。

Q.004 / 价格有多新？

供应商有价格接口的用实时价，没有的用公开价目表。每次运行在花钱前都会重新报价。

Q.005 / 能路由大模型调用吗？

不能。文本模型交给 LiteLLM 和 OpenRouter。getcheapapi 只管付费的数据与媒体 API。

Q.006 / 怎么新增供应商或修正价格？

编辑目录文件，对线上供应商跑一遍免费的字段校验，然后提交 Pull Request。
