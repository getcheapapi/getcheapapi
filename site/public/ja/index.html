機能

まず見積もり、支払いはその後。

001 / プロバイダーではなく機能で呼ぶ

serp.google、x.search、keyword.volume、image.generate。各機能は複数プロバイダーのルートに対応し、フィールドの対応付けとバッチ化も済んでいます。

002 / 全ルートに価格を

ローカルキャッシュから：価格 API があるプロバイダーはライブ価格、ないものは公開価格表。キーを持っていないルートも見積もるので、キーを追加したらいくら節約できるか分かります。

003 / 支払い直前に再見積もり

呼び出しの直前に価格を更新。AnyAPI は最安ソースに固定し、フェイルオーバーをオフにします。

004 / 超えない予算

毎回まず見積もり、--max-usd を超えれば拒否。デフォルトの上限は 0.1 ドルです。

005 / 402 で停止

402 では終了コード 2、最初の失敗で停止。エージェントはこれを再試行ではなく停止と読みます。

006 / 価格ベースライン

最安価格が急に上がったら、新しい価格を承認するまで実行を止めます。

007 / 重複排除とバッチ化

入力は重複を除き、プロバイダーが対応していればクエリのリストを 1 回のバッチで実行します。

008 / すべての呼び出しを記帳

レスポンスを保存し、課金を ~/.getcheapapi に記録。getcheapapi spend がプロバイダーとエンドポイント別に集計します。

009 / メディアも

Yir 経由の画像・動画・音声生成も、ジョブごとに見積もり、サーバー側で上限を設定します。

010 / エージェント用スキル

フォルダを Claude Code、Codex などのエージェントにリンク。クローンからならパッケージをインストールせずに動きます。

インストールの前に

Q.001 / 無料ですか？

はい。MIT ライセンスで、アカウントも料金も不要です。プロバイダーには自分のキーで直接支払います。

Q.002 / プロバイダーごとにキーが必要？

いいえ、1 つで十分です。キーのないルートも見積もるので、キーを追加した場合の節約額が分かります。

Q.003 / データはそちらのサーバーを通りますか？

いいえ。価格キャッシュ、台帳、保存した結果はすべてあなたのマシンの ~/.getcheapapi にあります。通信は API 呼び出しそのものだけです。

Q.004 / 価格はどのくらい新しい？

価格 API があるプロバイダーはライブ価格、ないものは公開価格表。毎回、支払い直前に再見積もりします。

Q.005 / LLM の呼び出しもルーティングできますか？

いいえ。テキストモデルは LiteLLM や OpenRouter の領域です。getcheapapi は有料のデータ・メディア API 専用です。

Q.006 / プロバイダーの追加や価格の修正は？

カタログファイルを編集し、実際のプロバイダーに対して無料のスキーマチェックを実行して、Pull Request を送ってください。
